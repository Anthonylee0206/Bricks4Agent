自動容錯移轉 — Demo 小抄

B4A · failover-sim · 手機版講稿 + 指令
「自動容錯移轉的核心機制（自動選主＋失效自我隔離＋不腦裂）已驗證；真錢上線會先半自動當安全墊，等真錢冪等驗證完再全自動。」

⚡ 開場前（先在筆電跑好）

一鍵起儀表板（起 stack＋開瀏覽器＋監測）：
.\demos\failover-sim\start.ps1
→ 瀏覽器自動開 http://localhost:8090，看到兩張卡＋折線圖。
→ 這個 PowerShell 視窗保持開著（它是監測服務）。
建議先完整跑一次＋錄影備案，live 出包不怕。

🎤 講稿（邊操作邊講）

① 痛點（30秒）
「這是真錢交易控制平面。broker 死了誰管倉位？最天真的兩台互備會腦裂——兩台同時下單、重複下真錢單，比停機還慘。難題是：保證同一刻只有一個主在動作。」
② 架構（指儀表板，40秒）
「兩張卡＝兩個節點，綠色是現在的主、灰色是熱備。下面折線＝系統處理量，一直往上＝正在做事。背後 3 個見證者投票決定誰是主，主握『租約』每秒續約，沒續到就自動失去主權。」
③ 殺主（動手，1分鐘）
在另一視窗打： 
docker kill fsim-node-<綠的>
「我直接殺掉主節點，模擬當機。看——那張卡變紅、折線出現紅段（處理量停住）、頂部跳警報。幾秒後另一張卡變綠、折線繼續往上爬——秒級接手，處理量一秒沒停。」
（綠的是哪台？看儀表板提示那行，或卡片綠色那個）
④（重點）分區自我fence（1.5分）
把現任主從網路分區： 
docker network disconnect fsim-net fsim-node-<綠的>
「最危險：網路分區、機器還活著但連不到投票。它偵測到→自我隔離、停止寫入，即使程序還活著。對側接手。被分區那台一筆都沒偷寫——零腦裂、零雙下單。」 復原： 
docker network connect fsim-net fsim-node-<剛分區的>
⑤ 誠實收尾（30秒，加分）
「單機跑證機制正確，不證實體機燒掉也活（那要真多機）。但驗證設計可行，零成本可重現就夠。真部署就是把容器散到 3 台機，機制一模一樣。核心難題我證明了，剩下是工程落地。」

💻 Demo 指令（全集）

起 + 開儀表板.\demos\failover-sim\start.ps1
殺主docker kill fsim-node-<綠的>
分區docker network disconnect fsim-net fsim-node-<綠的>

把殺掉的拉回docker start fsim-node-<那台>

🛡 被挑戰時怎麼答（點開）
Q：單機模擬，真多機呢？
A：單機證機制正確；真多機網路要實測，但用的是真 etcd 共識、機制一樣。
Q：真錢自動切不危險？
A：正是為什麼真錢我選半自動（人工閘）——機制是自動的，但真錢加一道確認，等冪等層驗完再放全自動。刻意的安全決策。
Q：怎麼證明沒腦裂？
A：自我 fence——失去租約的舊主自己停寫；折線紅段就是它停手，work 計數全程單一寫者、沒被兩個主重複寫。
Q：為什麼不用 Kubernetes？
A：k8s 解多節點調度，但 broker 是有狀態單例，k8s 不自動解狀態複製、也管不到「交易所無法 fence」。我用租約自我 fence 直接解,比上整套 k8s 輕。
Q：etcd 自己掛了？
A：3 個組多數決，掛 1 個還能跑；掛 2 個才停——寧可停也不腦裂。
